# 🧠 Domain-Specific Skill: Trace Visualisation & Dashboard Standards

This skill governs the UI/UX design tokens, visual assets, coloring rules, trace diff displays, and interactive button behaviors for the **Failure Forensics Tool** frontend.

---

## 🎨 1. Node Colour Coding Conventions

When rendering pipeline execution graphs or node networks, color schemes must strictly correspond to execution telemetry to ensure instantaneous cognitive diagnosis:
* **Healthy Spans**: `#22c55e` (Vibrant Emerald Green) ➔ Step executed successfully and reported a confidence score > 2.
* **Low Confidence Spans**: `#eab308` (Vibrant Amber Yellow) ➔ Step executed successfully but reported a `confidence_score` ≤ 2.
* **Root-Cause Anomaly Spans**: `#ef4444` (Premium Coral Red) ➔ The node identified by the backward trace analyzer as the primary failure vector.
* **Unexecuted/Skipped Spans**: `#94a3b8` (Slate Gray) ➔ Downstream steps that were aborted due to upstream failures.

---

## 📊 2. Three-Column Diff View Layout

Failed traces must present comparative data side-by-side. The dashboard must render a strict three-column layout, which must never collapse to single rows on desktop views:
1. **Column 1: "Step Received" (Left)**
   - Renders the exact input payload (arguments or Pydantic fields) passed into the step.
2. **Column 2: "Step Produced" (Center)**
   - Renders the actual output payload (serialized JSON or textual summary) generated by the step.
3. **Column 3: "Expected Output" (Right)**
   - Renders the baseline correct text or ground-truth values from the golden dataset.

> [!TIP]
> Highlight payload divergences between columns 2 and 3 in soft amber background styling to direct the user's attention straight to the mutation.

---

## ⚡ 3. Flag Button Interaction Rules

The UI must provide a "Flag Trace" or "Analyze Failure" action button for every abnormal execution:
* **Inline Execution**: Clicking the button must invoke `/trace-failure` asynchronously on the server.
* **Loading telemetry**: Transition the button immediately to a disabled, pulsing loading state with text: `Analyzing Trace Telemetry...`.
* **State Preservation**: The diagnostic report must render directly below the visual node graph without triggering a full Streamlit page reload.

---

## ● 4. Confidence Score Pip rows

* Never display confidence ratings as raw percentages (e.g., `60%`) or naked numbers (e.g., `3/5`).
* **Visual Standards**: Represent confidence as a five-pip filled bullet row using high-contrast Unicode symbols:
  * Score 5 ➔ `● ● ● ● ●`
  * Score 4 ➔ `● ● ● ● ○`
  * Score 3 ➔ `● ● ● ○ ○`
  * Score 2 ➔ `● ● ○ ○ ○`
  * Score 1 ➔ `● ○ ○ ○ ○`
  * Untested ➔ `○ ○ ○ ○ ○`
* Render low confidence rows (≤ 2 pips) in amber coloring to signal warning thresholds.
